Diagnóstico Geral da Plataforma

O Marketing HUB apresenta uma base técnica com arquitetura moderna, com contratos 100% tipados via tRPC v11, ORM Drizzle com migrações centralizadas, RBAC robusto em 95% dos procedimentos e excelente adoção de Tailwind e Radix UI.

O novo subsistema de MCP Server (Model Context Protocol) foi perfeitamente estruturado com hash seguro de tokens (SHA-256), autenticação Bearer e 12 ferramentas de Trade Marketing já operacionais. Contudo, a auditoria revelou pontos críticos de segurança no fluxo de autenticação tradicional (força bruta no 2FA) e pequenas divergências de fuso horário e roteamento que devem ser sanadas antes do deploy em produção.

✅ Principais Pontos Fortes

  • Zero Erros de Tipagem: pnpm check executa com 0 erros em todo o frontend e backend.
  • Build de Produção Saudável: O bundle de produção Vite e esbuild compila limpo sem quebras.
  • MCP Seguro por Design: Tokens nunca são gravados em texto claro (somente SHA-256) com prefixo canônico mcp_hub_....
  • Padrão Operacional Consistente: O módulo de Ações serve como referência sólida para lista → detalhe → diálogo.
  • Contratos tRPC 100% Casados: Zero incompatibilidade entre chamadas do cliente e roteadores do servidor.

⚠️ Pontos de Atenção Crítica

  • Força Bruta no 2FA / Reset: Códigos de 6 dígitos podem ser testados sem bloqueio dentro dos 10 minutos de TTL (SEC-01).
  • Timezone Offset em Testes: Conversão UTC (toISOString) quebra teste unitário em ambiente local GMT-3 (BUG-01).
  • Endpoint MCP no Dev Server: Falta registro do endpoint em dev-index.ts (funciona em prod, dá 404 em dev).
  • Link Quebrado em Cadastros: Card "Modelos de Campanha" não abre o workspace correspondente.
  • Caixas Amarelas no Dark Mode: Classes sem dark: ofuscam telas de Perfil e Usuários.
SEC-01 • CRÍTICA Ausência de Rate Limiting e Lockout na Verificação do Código 2FA e Reset de Senha
server/routers/localAuth.ts:279-317 & 379-423
Os procedimentos verifyLoginCode e resetPassword validam um código numérico de 6 dígitos (espaço amostral de 1.000.000 de combinações). O código possui validade de 10 minutos (ttl: 600.000ms), mas não possui limitação de tentativas de erro por IP, e-mail ou sessão. Um invasor pode disparar 5.000 requisições por segundo e adivinhar o código antes que ele expire, sequestrando contas de administradores.

Impacto & Risco

Bypass completo de autenticação de dois fatores e redefinição não autorizada de senhas de usuários privilegiados via força bruta.

Ação de Mitigação Proposta

Adicionar contador de tentativas (máximo 5 falhas). Após a 5ª tentativa inválida, destruir o código temporário e bloquear novas tentativas por 15 minutos.

// Proposta de Mitigação: const attempts = verificationAttempts.get(codeKey) || 0; if (attempts >= 5) { verificationCodes.delete(codeKey); throw new TRPCError({ code: 'TOO_MANY_REQUESTS', message: 'Limite de tentativas excedido. Solicite novo código.' }); } if (record.code !== input.code) { verificationAttempts.set(codeKey, attempts + 1); throw new TRPCError({ code: 'BAD_REQUEST', message: `Código incorreto. (${4 - attempts} tentativas restantes)` }); }
SEC-02 • ALTA Vulnerabilidade de Stored XSS via Upload de Favicon SVG
server/routers/settingsBranding.ts:167 & server/_core/storageProxy.ts
A rota uploadAppFavicon aceita arquivos com mimetype image/svg+xml sem sanitizar tags <script>, atributos onload= ou entidades XML maliciosas. Como o proxy de arquivos em storageProxy.ts serve o favicon com cabeçalho Content-Disposition: inline sob o mesmo domínio da aplicação, scripts maliciosos contidos no SVG serão executados no navegador de qualquer usuário logado que visualizar a página.

Impacto & Risco

Execução de JavaScript arbitrário no contexto da sessão do usuário, permitindo roubo de cookies não-HttpOnly, extração de dados e CSRF silencioso.

Ação de Mitigação Proposta

Sanitizar SVGs com DOMPurify / biblioteca de parsing XML estrito ou rejeitar SVG no favicon, exigindo PNG/ICO rasterizados com magic bytes validados.

SEC-03 • ALTA Segredos Operacionais e Senhas de Terceiros em Texto Claro no Banco de Dados
server/routers/settingsRegistry.ts & drizzle/schema.ts:app_settings
Configurações críticas como senhas de SMTP, credenciais de gateway SMS, OpenAI API keys e chaves de clientes de integração são gravadas em texto puro (plaintext) na tabela app_settings. Qualquer acesso de leitura ao banco ou backup expõe os segredos corporativos.

Impacto & Risco

Vazamento de credenciais de e-mail corporativo, serviços de IA pagos e gateways de mensageria em caso de dump acidental ou acesso ao banco.

Ação de Mitigação Proposta

Implementar camada de cifragem transparente com AES-256-GCM para chaves sensíveis catalogadas (ex: isSecret: true) usando ENCRYPTION_KEY de ambiente.

SEC-04 • ALTA Tokens de Sessão JWT Válidos por 1 Ano Não São Invalidados Após Redefinição de Senha
server/routers/localAuth.ts & server/_core/context.ts
O JWT gerado na autenticação possui validade de 365 dias (expiresIn: "365d"). Quando o usuário altera ou redefine sua senha, os tokens emitidos anteriormente permanecem válidos porque a validação do token não compara a data de emissão (iat) com o timestamp de atualização de senha (users.passwordUpdatedAt).

Impacto & Risco

Se um dispositivo for furtado ou uma sessão for comprometida, trocar a senha não desconecta as sessões ativas do atacante durante até 1 ano.

Ação de Mitigação Proposta

No createContext, rejeitar o token se payload.iat * 1000 < user.passwordUpdatedAt.getTime() e reduzir a expiração máxima para 7 a 30 dias com refresh rotativo.

SEC-05 • ALTA Elevação de Privilégio: Gestor Regional com Acesso a Procedimentos Destrutivos do Sistema
server/authorization.ts:167 & server/routers/settingsRegistry.ts
O papel regional_manager possui a permissão settings.write. No entanto, o router settingsRegistry agrupa sob settings.write procedimentos de infraestrutura crítica como clearModuleData (apaga em massa tabelas inteiras de campanhas, ações e custos) e updateSystem (reinício e migrações).

Impacto & Risco

Um gestor de campo pode disparar intencionalmente ou por engano a exclusão de todos os registros operacionais da empresa sem ser Administrador do Sistema.

Ação de Mitigação Proposta

Mudar clearModuleData e updateSystem para exigir adminProcedure exclusivo ou permissão específica system.danger_zone.

SEC-06 • MÉDIA Upload de Imagens em Configurações Sem Checagem de Magic Bytes
server/routers/settingsRegistry.ts:uploadSettingImage
Enquanto o módulo de evidências de trade marketing em server/storage.ts possui a função hasSupportedFileSignature, os uploads de logo e imagem em configurações validam apenas a extensão informada no MIME type pelo cliente, permitindo upload de executáveis renomeados para .png.

Impacto & Risco

Armazenamento de arquivos potencialmente maliciosos na pasta pública de uploads do servidor.

Ação de Mitigação Proposta

Reutilizar hasSupportedFileSignature(buffer) em todos os endpoints de upload de configurações.

SEC-07 • MÉDIA Ferramentas MCP Sem Validação de Schema em Runtime e Bypass de Transições
server/mcp/tools.ts:executeTool
Na tool atualizar_status_acao do MCP Server, a alteração de status não passa pelo validador canUpdateActionStatus da máquina de estados do sistema. Uma IA conectada via MCP pode forçar uma ação do status cancelada diretamente para concluida ou paga sem passar pelas etapas de aprovação e evidências.

Impacto & Risco

Inconsistência de fluxo de trabalho operacional e aprovação financeira fraudulenta via agente IA.

Ação de Mitigação Proposta

Importar e invocar as mesmas regras de validação de transição de status (máquina de estados finita) de actions.ts na execução das tools do MCP.

SEC-08 • MÉDIA Cookie de Sessão com Configuração Excessivamente Permissiva (SameSite=None)
server/_core/cookies.ts:32
Quando rodando em HTTPS, o cookie de autenticação é setado com SameSite: "none". O recomendável para aplicações corporativas sob o mesmo domínio é SameSite: "lax", evitando o envio acidental de cookies em requisições cross-site disparadas por sites externos.

Impacto & Risco

Risco potencial de CSRF caso endpoints legados que aceitam GET realizem mutações de estado.

Ação de Mitigação Proposta

Ajustar para sameSite: "lax" por padrão, permitindo "none" apenas quando expressamente configurado para iframes autenticados de terceiros.

SEC-09 • MÉDIA Vazamento de Stack Traces e Mensagens Internas de Banco em Erros tRPC
server/routers/actions.ts & server/routers/campaigns.ts
Alguns blocos catch repassam error.message diretamente para o TRPCError retornado ao usuário. Isso pode vazar nomes de colunas, restrições de chave estrangeira do PostgreSQL/MySQL e caminhos do sistema de arquivos.

Impacto & Risco

Enumeração de estrutura interna do banco e tecnologias de backend por usuários curiosos.

Ação de Mitigação Proposta

Sanitizar as mensagens de erro em produção, registrando o stack trace original apenas no logger de servidor.

SEC-10 • MÉDIA Rate Limiting de Login Baseado em Memória Volátil do Processo Node
server/routers/localAuth.ts:loginAttempts
O mapa de tentativas de login é armazenado em uma variável Map em memória. Se a aplicação rodar em múltiplos nós com cluster/load balancer ou se o processo for reiniciado por um crash intencional, a proteção de bloqueio por IP é zerada.

Impacto & Risco

Perda de estado de bloqueio de força bruta em ambientes clusterizados ou reinicializações.

Ação de Mitigação Proposta

Persistir contadores de bloqueio em tabela dedicada de banco ou cache compartilhado Redis para clusters.

SEC-11 • BAIXA Falta de Cabeçalhos Restritivos de Segurança (CSP & HSTS) no Express
server/_core/index.ts & dev-index.ts
Embora os cabeçalhos X-Content-Type-Options: nosniff e X-Frame-Options: SAMEORIGIN estejam configurados, faltam cabeçalhos modernos como Content-Security-Policy e Strict-Transport-Security (HSTS).

Impacto & Risco

Degradação de pontuação em auditorias de segurança automatizadas (ex: Mozilla Observatory A+).

Ação de Mitigação Proposta

Adicionar middleware helmet com políticas adequadas de scripts e estilo do Tailwind.

BUG-01 • P0 Falha no Teste Unitário: Conversão UTC em Fuso Horário Local (GMT-3)
client/src/pages/ActionsEventsWorkspace.test.tsx & ActionsWorkspace.tsx
O teste ActionsEventsWorkspace.test.tsx falha ao validar o valor de um input datetime-local preenchido com 15:00 porque o componente faz a formatação usando new Date(val).toISOString().slice(0, 16). O método toISOString() converte o horário local de Brasília (UTC-3) para o fuso UTC (+3 horas), gerando 18:00 em vez de 15:00.

Causa Raiz

Uso de toISOString() para inputs HTML locais sem compensar o deslocamento de timezone do navegador.

Correção Determinística

Implementar função auxiliar formatLocalDateTime(date) que extrai ano, mês, dia, hora e minuto locais (ex: date.getFullYear(), date.getHours()) com padding zero.

// Helper recomendado para ActionsWorkspace.tsx: export function formatLocalDateTime(date: Date | string | null | undefined): string { if (!date) return ''; const d = typeof date === 'string' ? new Date(date) : date; if (isNaN(d.getTime())) return ''; const pad = (n: number) => String(n).padStart(2, '0'); return `${d.getFullYear()}-${pad(d.getMonth() + 1)}-${pad(d.getDate())}T${pad(d.getHours())}:${pad(d.getMinutes())}`; }

ARCH-01 • P1 Criação de Campanhas no MCP sem Transação Atômica de Banco
server/mcp/tools.ts:criar_campanha
Na ferramenta criar_campanha, a inserção da entidade campanha na tabela campaigns e a subsequente inserção da dotação orçamentária em campaign_allocations ocorrem em chamadas separadas sem envolver em database.transaction(...). Caso ocorra uma falha de rede ou violação de integridade no segundo insert, uma campanha órfã sem orçamento permanece salva no banco.

Impacto

Risco de inconsistência e orfandade de registros em caso de falha transitória durante execução de IA.

Ação de Mitigação Proposta

Envolver as queries de criação em bloco await database.transaction(async (tx) => { ... }).

UI-01 • P1 Refinamento Estético e de Acessibilidade no McpTokensManager

O novo gerenciador de tokens MCP precisa ser alinhado aos padrões estéticos de OperationalPatterns.tsx:
